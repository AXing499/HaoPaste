# 产品与技术路线

## 0. 方向

HaoPaste 的长期定位是「Mac 上最快、最安心的剪贴板工作台」：

- 快：全局唤起、键盘优先、毫秒级搜索。
- 稳：本地优先、无外部依赖、异常可恢复。
- 安全：不窥探敏感内容，不强制申请高权限。
- 原生：符合 macOS HIG，视觉与系统一致。

当前优先级：**把日常使用闭环做扎实**，再扩展为动作平台。

## 5. 非目标

- 不做需要登录的云服务。
- 不做广告、用户画像或遥测上报。
- 不强制要求辅助功能权限；自动粘贴必须显式 opt-in。
- 不优先考虑 Mac App Store（当前为本地完整剪贴板能力，未启用沙盒）。
- 不同步到 Windows / Linux。

## 6. 技术债与风险

| 项目 | 影响 | 计划 |
| --- | --- | --- |
| 快捷键写死 `⌥⌘V` | 冲突时无法解决 | v0.2 自定义快捷键 |
| 无自动化测试 | 回归风险 | v0.2 单元 + UI smoke + CI |
| ad-hoc 签名 | 外部用户可能被 Gatekeeper 拦截 | v0.2 Developer ID + 公证 |
| JSON 全量写盘 | 大数据量下 I/O 增加 | 规模上来后迁移 SQLite / SwiftData |
| 全量历史加载内存 | 极端情况下占用升高 | 分页 / 数据库游标 |
| 大文本主线程处理 | 超大复制可能造成轻微卡顿 | 哈希与分类迁移到后台 |
| 仅保留纯文本输出 | 富文本复制丢失格式 | v0.3 富文本类型 |
| 图片只保留首帧 | GIF 动效丢失 | v0.3 |
| 密码管理器过滤为尽力而为 | 特定应用可能未标注隐藏类型 | 应用级排除规则 + 隐私模式 |
| App Nap / 轮询能耗 | 后台能耗虽低但非零 | 使用活动令牌；评估事件驱动可能性 |

## 7. 已做的关键取舍

1. **JSON 而非 SwiftData**
   200 条规模下 JSON 更轻、无迁移成本、可直接查看和导出。未来通过 Repository 边界迁移。
2. **轮询而非系统通知**
   `NSPasteboard` 没有公开的变更通知；轮询 `changeCount` 是社区稳定做法。350ms 在延迟与能耗间折中。
3. **不自动粘贴**
   避免申请 Accessibility，减少权限摩擦和安全风险。用户按 `⌘V` 的额外一次按键换来确定性。
4. **未置顶 200 条，置顶无限**
   与用户预期一致：我主动保留的内容不应被自动删除。
5. **无沙盒**
   保留完整剪贴板与全局快捷键能力，优先本地工具属性，不走 Mac App Store。
6. **AppKit 面板 + SwiftUI 内容**
   AppKit 负责窗口层级、焦点、全局快捷键和键盘监听；SwiftUI 负责声明式界面与动效，兼顾原生和开发效率。
